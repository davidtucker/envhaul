# Configuration

envhaul reads a YAML file, `envhaul.yaml` by default.

## Finding the config file

envhaul uses the first match of:

1. `--config` / `-c`
2. the `ENVHAUL_CONFIG` environment variable
3. `envhaul.yaml`, `envhaul.yml`, `.envhaul.yaml` or `.envhaul.yml` in the
   current directory or a parent, stopping at the repository root (the first
   directory containing `.git`)

Use one file per environment, for example `envhaul.yaml` for development and
`envhaul.staging.yaml` for staging:

```sh
envhaul -c envhaul.staging.yaml sync
```

## Editor support

Add this first line to get completion and validation in editors that use the
YAML language server (VS Code, JetBrains, Neovim, Zed):

```yaml
# yaml-language-server: $schema=https://raw.githubusercontent.com/davidtucker/envhaul/main/schema/envhaul.schema.json
```

## Top-level keys

| Key | Required | Description |
| --- | --- | --- |
| `version` | no | Schema version. Only `1` exists; it is the default. |
| `name` | no | Environment name, shown in generated file headers. |
| `description` | no | Free text. |
| `aws_profile` | no | Default AWS profile for references without `@profile`. Overridden by `--profile`. When unset, the SDK default applies (`AWS_PROFILE`, then `default`). |
| `aws_region` | no | Region for every request. Overridden by `--region`. When unset, each profile's own region from `~/.aws/config` is used. |
| `ssm_prefix` | no | Joined onto SSM paths that don't start with `/`. Must start with `/`. |
| `secret_prefix` | no | Prepended to Secrets Manager ids that aren't ARNs, e.g. `myapp/dev/`. |
| `components` | yes | Map of component name to settings. Each component writes one file. |

## Components

```yaml
components:
  api:
    description: Backend API     # optional, shown in shell completion
    env_file: services/api/.env  # relative to the config file
    vars:
      KEY: value
```

| Key | Required | Description |
| --- | --- | --- |
| `env_file` | yes | Output path. Relative paths resolve against the config file's directory, not the current directory. Two components can't write the same file. |
| `vars` | yes | Variables, written in the order listed. |
| `description` | no | Free text. |

Component names can't contain spaces or slashes.

## Variables

Variable names must match `[A-Za-z_][A-Za-z0-9_]*`. Values can be:

- **inline:** `ENV: dev`
- **a reference:** `API_KEY: "{{ssm:api/API_KEY}}"`
- **a template** mixing both:
  `DB_URL: "postgresql://{{secret:db#user}}:{{secret:db#pass|urlencode}}@host/db"`

See [References and pipes](references.md) for the syntax.

!!! tip "Values are taken literally"
    envhaul keeps every scalar exactly as written, so `1.10`, `0755`, `yes` and
    `1e3` reach your `.env` unchanged instead of becoming `1.1`, `493`, `true`
    or `1000`. An empty value, `~` or `null` becomes an empty string. Quote
    values that contain `{{`, `#` or `: `.

## Generated files

Each env file starts with a header naming the config it came from, followed by
the variables in config order:

```sh
# Generated by envhaul from envhaul.yaml (dev). Do not edit; changes are overwritten.
# Regenerate with: envhaul sync api

APP_ENV=development
DATABASE_URL=postgresql://admin:p%40ss@localhost/acme
GREETING='hello world'
```

- envhaul owns these files: every `sync` rewrites them completely. Put
  local-only values in the config, or in a separate file your tooling loads
  (such as `.env.local`).
- Files are written atomically (a temp file, then rename) with mode `0600`,
  and are left untouched when the content hasn't changed.
- Values are written bare when they only contain safe characters, in single
  quotes when they contain no `'` or newline, and in double quotes with `\\`,
  `\"`, `\n` and `\r` escapes otherwise. Docker Compose, python-dotenv, Node
  `dotenv` and Vite all read these forms the same way.
- `sync` warns when a generated file isn't ignored by git.

## Missing values

A reference to a parameter or secret that doesn't exist (or a `#key` that a
JSON secret doesn't have) is written as an empty string with a warning. This
keeps optional integrations from blocking everyone else. To change that:

- add `|default:value` to the reference to provide a fallback, or
- run with `--strict` to fail instead (useful in CI).

Errors such as expired credentials or denied access always fail, and nothing
is written.
